# Single-pass clustering: CTE variants and evaluation (local, not tracked)

## cte_variants/

Toy recursive-CTE versions of single-pass clustering (Jaccard similarity over term
sets, 6 documents). They back the discussion of standard SQL in Section 2.2.1 of the
paper; the listings are reproduced in the paper's note `notes/cte-single-pass.tex`.

- `versions-A-B-and-rejected.sql`: test data; version (A), the cluster set packed
  into one array with UDFs; version (B), the same without UDFs; and the three
  formulations PostgreSQL rejects (ORDER BY/LIMIT, aggregate, and subquery over the
  working table).
- `version-C-relational.sql`: version (C), clusters kept as rows, using only a
  recursive CTE, window functions, joins, CASE, and CAST.
- `timing-A.sh`, `timing-C.sh`, `rows_count.sql`: scaling runs of (A) and (C) on
  random documents.

## evaluation/

The evaluation of single-pass clustering, on the synthetic datasets Synthetic-Tweets
and Synthetic-News, in two separate evaluations:

- `evaluation/ABLATION.md`: the ablation of the HadathSQL driver UDF, against variants
  that each lack one optimization (indexes, summed centroids, prepared statements);
  also the datasets, how to run on a server, and the preliminary laptop runs.
- `evaluation/COMPARISON.md`: HadathSQL against other solutions: the Standard SQL CTE
  (run on smaller data) and an external pipeline (to be defined).

The folder also keeps the drivers and the Array CTE (non-standard) of the preliminary
runs. All of them compute exactly the same clusters.

- `gen_synthetic_data.sql`: synthetic corpus `sp_docs(doc_id, txt, ts)` (settings
  `synthetic_tweets`, `synthetic_news`).
- `driver_variant_*.sql`: the basic, summed, summed + indexed, summed + indexed +
  prepared, and mean + indexed drivers, and the four ablation variants of the
  HadathSQL driver (`driver_variant_hadathsql_*.sql`, generated by
  `make_ablation_variants.py`); the HadathSQL driver is
  `single_pass_clustering/sp_clustering.sql`.
- `setup_cte.sql`, `prep_cte_*.sql`, `run_cte_*.sql`: the CTEs and their input
  preparation.
- `ablation.conf`, `comparison_cte.conf`, `small_evaluation.conf`: settings of the
  ablation, of the CTE comparison, and of the preliminary driver comparisons.
- `setup_db.sh`: installs everything into an empty database (e.g. on the remote server)
  and records the machine configuration in `machine.txt`.
- `run_point.sh`, `sweep.sh`, `render_results.py`: one point, a sweep (from a config), and the
  results tables in `ABLATION.md` and `COMPARISON.md`.
- `results_*.csv`: raw results.
- `pgdata/`: the test PostgreSQL instance (port 54329, user `test`, database
  `hadath`). Start it with
  `pg_ctl -D pgdata -o "-p 54329 -c unix_socket_directories='' -c listen_addresses=localhost" -l pgdata.log start`.
